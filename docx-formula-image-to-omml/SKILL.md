# docx 公式图片 → 原生公式（OMML）规范化

## 适用场景

一份 docx 里公式是**从别处截图/粘贴的图片**，导致：不能编辑、不能检索、编号是烙在图里的、正文夹了 Unicode 伪角标（`Ψⱼₗₖ`、`hᶜᵗˣₖ`、`Ẑₗᵖʳᵉᵈ`）。目标是把它们全部转成 Word 原生公式，并补上规范的公式编号。

## 铁律

1. **先备份**，命令里第一步就是 `cp` 原文件到带时间戳的副本。用户没明说也要做。
2. **产物写新文件**，不要原地覆盖；媒体文件必须字节级原样复制（`writestr(item, data)` 保留原 ZipInfo）。
3. **不要用 python-docx** 做这件事。100MB 级、几千段的文档直接按 `<w:p>` 切分原 XML 做字符串级替换，快且可控。
4. 任何一步都要能被用户复核：所有中间产物（图片清单、LaTeX 映射、编号日志）落盘。

## 环境前提

- Python（需 PIL）：用带 PIL 的解释器；pandoc 必须可用（`pandoc -f markdown -t docx` 会产出标准 OMML）。
  - 本机：python `~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`（有 PIL）；
    pandoc 在 `C:\Users\14711\anaconda3\Scripts\pandoc.exe`。
- pandoc 是原生 Windows 二进制，**路径必须传 Windows 形式**（`D:\...`），Git Bash 的 `/d/...` 它会报 does not exist。

## 步骤

### 1. 摸底

```python
z = zipfile.ZipFile(SRC)
xml = z.read('word/document.xml').decode('utf-8')
xml.count('<w:drawing>'), xml.count('<m:oMath>')
```
同时导出段落大纲（段号 / pStyle / 可见文本 / 是否含图）到 `doc_dump.txt`，供后续判断章节归属与公式引用。

### 2. 分类（最关键的一步）

对每个 `<w:drawing>` 取 `<wp:extent cx cy>`（EMU，`/360000` = cm）与 `r:embed` → 媒体文件。用**段落是否含正文**而不是尺寸来区分：

| 类型 | 判据 |
|---|---|
| 展示公式 | 该段**不含任何非空白文本**，且高度 < 2.6 cm |
| 行内公式 | 该段**含正文**，且高度 < 1.5 cm |
| 插图 | 其余（含与正文同段的大图 —— 这类最容易被误判成行内公式） |

两个必须记住的坑：
- **高度阈值会漏掉多行公式块**（`cases`、对齐式），它们能到 3~6 cm。要单独把 2.6~7 cm 的"独段图"全部拉出来看一眼，用联系表人工确认哪些其实是公式 —— 判断标准是"纯黑白排字"还是"有图表/照片/彩色"。
- **与正文同段的插图**（`...如图39所示。[图片]`）会被"同段"规则误收进行内公式。所以行内公式必须再加高度上限。

### 3. 转写（人工/多模态识读）

把待转写图片按类型拼成联系表，用多模态读图逐批转写：

- 展示公式：单列、宽度拉满、每张 12 个一屏（公式要看清上下标和分式）。
- 行内公式：3 列网格、每格 490px、每屏 42 个（符号小，需要放大 4~6 倍）。
- **透明 PNG 必须先合成到白底**，否则 `.convert('RGB')` 会把透明像素变黑，整张图成黑块：
  ```python
  im = im.convert('RGBA'); bg = Image.new('RGBA', im.size, (255,255,255,255))
  im = Image.alpha_composite(bg, im).convert('RGB')
  ```
- 每格左上角写 `序号 文件名` 标签，**按序号转写**、再用脚本把序号映射回文件名 —— 不要凭肉眼抄文件名（`image361` / `image381` 极易看错，差一个数字就串位）。
- 同一张图里可能并排两条带编号的公式（`cases` 或两行 = 两个公式），要拆成两条各自编号。
- 用 md5 去重：同一符号重复出现很多次，去重后转写量能降一截。

### 4. LaTeX → OMML

一次 pandoc 调用批量转换，比每张调用一次快几十倍：

```python
md = '\n\n'.join('$' + latex + '$' for latex in all_latex)   # 行内数学形式 → <m:oMath>
subprocess.run([PANDOC, '-f','markdown','-t','docx','-o',dxp,mdp])
x = zipfile.ZipFile(dxp).read('word/document.xml').decode('utf-8')
x = re.sub(r'</?m:oMathPara[^>]*>', '', x)                   # 去掉段落级包裹，只留 <m:oMath>
found = re.findall(r'<m:oMath>.*?</m:oMath>', x, re.S)        # 按顺序即按输入顺序
```
校验 `len(found) == len(input)`。要点：
- 用 `$...$`（行内）而不是 `$$...$$`（会包成 `<m:oMathPara>`）。产出 `<m:oMath>` 才能自由嵌进自己构造的段落。
- LaTeX 里的 `\begin{cases}`、`\hat`、`\mathbb`、`\mathcal`、`\boldsymbol` pandoc 都能转。
- 撇号/上标要写 `{A^\prime}^{m}_{ij}`，直接 `A'^{m}_{ij}` 会挂错位置。

### 5. 重建 document.xml

用 `re.finditer(r'<w:p [^>]*>.*?</w:p>|<w:p/>', xml, re.S)` 切分，**注意原文档里 `<w:p>` 都带属性**（`<w:p w14:paraId="...">`）；自己新建段落时写 `<w:p>` 不带属性也可以，但那样后续正则要同时匹配 `<w:p ...>` 和 `<w:p>`。

**展示公式** → 换成一个"居中制表位 + OMML + 右对齐制表位 + 编号"的段落：

```xml
<w:p><w:pPr>
  <w:tabs><w:tab w:val="center" w:pos="4153"/><w:tab w:val="right" w:pos="8306"/></w:tabs>
  <w:jc w:val="left"/></w:pPr>
  <w:r><w:tab/></w:r><m:oMath>…</m:oMath>
  <w:r><w:tab/><w:t>(1)</w:t></w:r>
</w:p>
```
- 制表位按节算：`右 = pgSz.w - pgMar.left - pgMar.right`，`居中 = 右/2`。A4 纵向（w=11906，左右各 1800）→ 8306 / 4153。
  **同一文档可能有多个 sectPr**（含横向页），要按段落位置定位它属于哪一节，否则制表位会错。
- `<w:tabs>` 在 `w:pPr` 里的**位置有 schema 顺序要求**：在 `widowControl/numPr/pBdr/shd` 之后、`spacing/ind/jc` 之前。直接插在 `<w:pPr>` 后是错的。`jc` 必须在 `ind` 之后。
- 居中制表位的语义正好是"后续内容以该制表位为中心排" → 公式居中、编号贴右边距，就是想要的效果。

**行内公式** → 把**整个 `<w:r>` 运行**替换成裸 `<m:oMath>`（不要塞在 `<w:r>` 里）。一个 run 里可能有多张图或图文混排，要按 token 顺序（`<w:drawing>` / `<w:t>`）重建，别只处理第一张。

**Unicode 伪角标** → 在 `<w:t>` 文本里按字符切段，生成带 `<w:vertAlign w:val="subscript|superscript"/>` 的 run，字形映射：
`₀₁₂…₉ ₊₋₌ ₐₑₒₓₕₖₗₘₙₚₛₜᵢᵣᵤᵥⱼ` → 真下标，`⁰¹²…⁹ ⁱⁿᵀᵃᵇᶜᵈᵉᶠᵍʰʲᵏˡᵐᵒᵖʳˢᵗᵘᵛʷˣʸᶻ` → 真上标。
注意：从 `<w:t>` 里取到的文本**已经是 XML 转义过的**，切段后不要再 `escape`，否则 `&amp;` 会变 `&amp;amp;`。

### 6. 编号方案

从文档自身推方案，不要凭空定。**先看正文里已有的 `公式（n）` 引用**：如果某个小节引用（1）…（19）而该小节正好有 19 个展示公式，那方案就是"按小节重新从 (1) 开始"。图里已经烙了编号的（很多是 MathType/LaTeX 截的图）正好可以当交叉校验。

把图片换成原生公式后，烙在图片里的编号会自然消失，必须自己补 —— 所以编号数据要单独放成一个表（`file → 编号`），改方案时只改表重建，不必重新识读。

`4_rebuild.py` 支持两种模式（第 4 个参数，默认 `section`）：

| 模式 | 编号 | 用途 |
|---|---|---|
| `section` | 每小节从 (1) 重新开始 | 论文按章编号的常规需求 |
| `global` | 全文从 (1) 连续排到 (N) | 用户说"从 1 一直往下排"时的需求 |

**只给行间（展示）公式编号，行内公式一律不编号** —— 这个前提要跟用户对齐，别把行内也编上。

#### 6.1 全局连续编号 + 正文引用同步（`global` 模式）

改编号方案时，正文里的「公式（n）」引用必须同步改，否则引用全部失效。要点：

1. **局部序号 → 全局序号用「公式数」而不是「图片数」累计**。一张图里可能并排两条公式（`cases`、对齐式），按图片累计会整体偏移。统计口径：
   ```python
   sec_count[s] += disp_n[d['file']]   # disp_n[file] = 该图里的公式条数
   ```
   然后用 `off` 前缀和得到 `L2G[sec] = {局部序号: 全局序号}`。
2. **匹配要能跨 run**。正文里的引用常被 Word 拆成多个 `<w:r>/<w:t>`（例：`式（` + `2.6-6` + `）` 是 3 个 run）。只在单个 `<w:t>` 里做正则替换会漏改。
   做法：把段落里所有 `<w:t>` 文本拼起来匹配，算出 `(start, end, new)` 改动区间，再按 run 的字符区间切片回填 —— **只重建被改动区间覆盖到的 run，其余 run 原样保留**（保格式）。
3. **标签序号与所在小节不一致的引用要人工核对**，别按标签里的章节号机械映射。典型例子：2.2.2 的正文写「式（2.6-6）」，实际指的是本小节第 6 个公式 `Ltotal`（原标签章节号是历史遗留的错号）。
   这类用手工核对表显式指定，并在脚本里留注释：
   ```python
   REF_OVERRIDE = [('2.2.2', '式（2.6-6）', '公式（%d）' % L2G['2.2.2'][6])]
   ```
4. **先扫全文有几种引用形态**再动手，别只改 `公式（n）`：
   ```python
   re.findall(r'.{0,4}(?:公式|式)\s*(?:（[^）]{1,12}）|\([^)]{1,12}\))', body)
   ```
   顺便统计每种形态出现几次、落在哪个小节、是否单 run —— 这份清单就是改写范围的定义。
5. 编号标签用半角 `(n)`、正文引用用全角 `公式（n）`：两者风格不同是正常的（标签贴右边距、引用在正文里）。若用户要求统一，改 `build_display` 里的 `lab` 即可。

#### 6.2 对「已经被别人改过」的文档做重编号（`scripts/6_renumber_display.py`）

真实场景：交付一版后，合作者在 Word 里继续改稿（增删章节、重排公式、甚至手动删掉编号），再丢回来让你「更新公式」。这时**公式图片已经没有了**，要做的是「重编号 + 版式统一」，不要重跑整条流水线。

先诊断，别急着改：

1. **先和上一版做包级对比**：`<w:drawing>` / `<m:oMath>` / `<m:oMathPara>` 计数、编号标签数、`word/media` 条目数、段落数。一眼就能看出对方动了什么（本例：drawing 69→49，说明 20 张图被换掉；oMath 300→410，说明新增了 110 个公式实例）。
2. **枚举行间公式**。判据两种，都要认：
   - **A 型（本技能产出）**：`pPr` 里有 `<w:tab w:val="center" w:pos="4153"/>` 且段内除编号外无可见文本；
   - **B 型（Word 原生显示公式）**：段内含 `<m:oMathPara>`。
   两种都要算入编号序列，否则编号会错位。
3. **`<m:oMathPara>` 必须归一**：Word 的显示公式把 `<m:oMath>` 包在 `<m:oMathPara>`（内含 `<m:oMathParaPr>`）里。要统一版式就得剥掉外层、只留 `<m:oMath>`，再套「制表位 + 公式 + 制表位 + 编号」。剥完 `oMathPara` 计数应为 0。
4. **数数别数错**：`p.count('<m:oMathPara')` 会把 `<m:oMathParaPr>` 也算进去（同一段出现 2 次），要用 `<m:oMathPara>` 带尖括号的精确匹配。同理 `p.count('<m:oMath')` 会把 `<m:oMathPara` 算进去。
5. **引用映射用「旧编号 → 新编号」**，不要用「小节内序号 → 全局」——因为对方可能已经删改过中间的小节，局部序号已经不可靠。做法：遍历行间公式时记下每段的旧标签与新标签，建 `OLD2NEW`，再改正文引用（跨 run 改法见 6.1）。
6. **改完必须跑「段落文本级 diff」**：变化应只出现在「行间公式段（文本变成编号）」和「引用段」两类，其余一字不变。
7. **行间公式数会变，编号区间也会变**：本例 1.2.2 从 19 条被改成 4 条，于是后面所有编号整体前移（旧 31→16、45→33、75→63），正文引用 `公式（45）` 同步改为 `公式（33）`。

**制表位有个必须踩过的坑**：`stops_for()` 只扫「段内 sectPr」，但**最后一节的页属性来自 body 级 sectPr**（它不在任何 `<w:p>` 里，是 `</w:p>` 之后 `</w:body>` 之前的那个）。漏掉它，收尾那一节的公式会拿到上一节（可能是横向页）的制表位，编号直接跑出页面。正确做法：段内 sectPr 逐个建节，再把 body 级 sectPr 作为「收尾节」补到最后。

顺带记住：横向页（`w:orient="landscape"`，`pgSz w:w="16838"`）的正文宽约 13958 twips，制表位要按节算，不能全文档写死 4153/8306。

### 6.3 混合态文档：前半章是图片公式、后半章已是原生公式（`scripts/archive/build_hybrid.py`）

另一类高频回稿：**只有第 1 章被换成了图片公式**，第 2/3 章是你之前转好的原生 OMML，还带着纯文本编号。这时不要整篇重做，也不要只当普通 6.2 处理。

诊断三步：

1. **先分段摸底**，把「图片公式区」和「原生公式区」分开：按段落号扫 `<w:drawing>` / `<m:oMath>`，看两边各自占比。本例第 1 章 16 条行间全是图、第 2/3 章 52 条全是原生带号。
2. **用后段的既有编号反推全文方案**。这是最省事也最准的办法：本例 16（前半图片）+ 52（后半已编号）+ 7（另有 7 条无号原生显示公式）= **75**，而后段开头正好是 **(20)** → 原稿就是全文连续 1..75，前半丢了 (1)–(19)。**编号方案是文档自己说出来的，不用猜。**
3. 方案有歧义时（比如「只编前半」也说得通），**问一句再动手**——因为要改后半段 52 条标签，属于会被事后质疑「你乱改」的动作。问的时候把推荐项放第一条并写明代价。

重建要点（相对 6.1/6.2 的增量）：

- **只改标签 `<w:t>` 里的纯数字**，段落的 `pPr`/制表位/公式 `oMath` 一律不碰 —— 后段本来就是对的，别重排。
- 后段的原生显示公式若是 `<m:oMathPara>` 且**无编号**，剥外层 + 去 `<w:sz w:val="22"/>`（Word 显示公式常带 11pt 显式字号，会和全文其他公式不一致）+ 补号。
- **扫行内图时必须用媒体白名单过滤**，否则会把真插图（`image1.jpeg` 这类）一起当公式替换掉。做法：`if 'I'+media not in omml: continue`，并在末尾 `assert 替换数 == 预期行内公式数`。
- 改正文引用前先确认该引用**是否落在单个 `<w:t>` 里**（本例整段文本就是一个 `<w:t>`，直接 `str.replace` 即可）。跨 run 才需要 6.1 的区间切分法。

### 6.4 逐条对照核对表（`scripts/archive/check_table.py`）——识读正确率的验收手段

图片公式转写最容易出错的一步是**识读**（上下标、粗体、分式）。转完给老板一份 HTML 核对表，左列原图、右列转换结果，让他 30 秒扫完 40 多条：

- 原图直接 base64 内嵌（`data:image/jpeg;base64,...`），不要引用外部文件。
- 公式渲染用 **MathML**：`pandoc -f markdown -t html --mathml`，浏览器原生支持、**不需要联网 CDN**（KaTeX/MathJax 在离线环境会挂）。
- 一次 pandoc 批量转，靠**标记切分**结果：在每条公式前插一行标记文本，再用 `re.split` 切断。
  ⚠️ 标记别用 `@@@1@@@` 这种形式 —— pandoc 的 markdown reader 会把它识别成 **citation** `[@1]`，切分全空。用纯字母数字如 `MKRd1MKR`。
- 深浅色主题跟着 IDE 走；浅色主题别用深底。

### 7. 校验（必做）

- `xml.etree.ElementTree.fromstring(document.xml)` 过 XML 合法性。
- zip 逐条目比对 `CRC`/name/size（用 `z.infolist()` 的 `CRC` 最省事），**必须只有 `word/document.xml` 有差异**（证明媒体没被动过）。
- 计数核对：`原有 oMath + 展示公式数 + 行内公式出现次数 == 新 oMath 数`；剩余 `<w:drawing>` 数 == 插图数。
- `vertAlign` 增量必须等于伪角标转换的 run 数（`sub` / `sup` 分别对），差一个都说明有段落被重复处理。
- **pandoc 反向解析**：`pandoc -f docx -t markdown 新文件.docx`，检查公式变成 `$...$`、角标变成 `~sub~` / `^sup^`、编号紧跟公式。这是不开 Word 也能验证 OMML 可用性的最强手段。
- 扫描 `剩余的伪角标字符数 == 0`。
- **编号与引用专项**（改编号方案后必查）：
  - 抽出所有编号标签，验证是严格递增且无重复的 `1..N`；
  - 抽出所有正文引用，逐个核对已在目标区间内，且旧标签（如 `式（2.6-6）`）无残留。
    注意 `公式（n）` 本身就含子串「式（n）」，用 `式（` 做残留检查会全是误报 —— 要排除前面是「公」的情况。
  - 段落文本级 diff（`difflib.SequenceMatcher`）确认变化面的"最小性"：改动应只出现在「展示公式段（文本变空 + 多了编号）」「伪角标段」「引用段」三类里，其他段落文本一字不变。
- **别用 python-docx 保存做交付**：它会把 `document.xml` 未引用的 `word/media/*` 全部丢掉（本例丢了 454 个孤儿媒体条目），包体从 561 条目掉到 107 条。直接用 `zipfile` 逐条目复制、只替换 `document.xml`。

### 8. 被质疑「你把图表顺序/交叉引用弄乱了」时怎么自证

改公式最容易背的锅就是「图表乱了」，因为老板只会觉得「你改过文件 = 文件坏了」。**用数据回答，不要辩解**。

三版对比法（`work/final_check.py`、`check_ref.py`、`locate_dup.py`）：

1. **对齐三份文件**：A = 你动手前的备份，B = 你的产出，C = 老板现在这版。三者都要比，才能证明「不是我」也「不是我之后才坏的」。
2. **按域类型抽序列，逐版本打印**，只要 A==B==C 就结案：
   - `SEQ 图` / `SEQ 表` 的**缓存值序列**（`fldChar separate→end` 之间的文本，取纯数字那个）；
   - `<w:drawing>` 后的 `r:embed` **rId 出现顺序**（图的实际排布顺序）；
   - `bookmarkStart@w:name` 集合；`REF _Ref\w+` / `PAGEREF` 列表；
   - 断链检查：`REF` 目标是否都在 bookmark 集合里；文档里 `未找到引用源` 出现次数。
3. **段落文本级 diff**，把变化段落逐条打出来。结论应是「只有公式段 + 引用段变了」。本例 4907 段里只差 72 段，全在公式上。
4. **逐个交叉引用做一致性核对**（最有说服力）：对每个 `REF` 域，取它指向的书签 → 找书签所在段落 → 从题注文本里抠出图/表号 → 和 REF 域的**缓存显示值**比。不一致的就是「真问题」，逐条报出来。
5. **A/B/C 三版都出现的缺陷 = 原始稿自带**，明确写「不是我引入的」，并给位置（para 号 + 上下文文本）。

常见的、**属于原始稿**的题注类缺陷（不要以为是自己的锅）：
- **同号题注**：某张图的 `SEQ` 缓存值与前一条相同（多为复制粘贴题注后没更新域），导致总题注数比最大号多 1。
- **REF 缓存偏 1**：题注被增删过，`SEQ` 重算过但 `REF` 域没刷新，于是正文「如图 15 所示」指向的却是「图 14」的题注。
- **题注丢样式**：题注段落被手动敲回车拆成两段，第二段（如「（气泡大小与FLOPs成正比）」）还留着 `pStyle=12`，第一段掉了样式。**这种 F9 治不了**。

**修法优先级**：能靠「Ctrl+A → F9 → 更新整个目录」解决的就别改 XML —— SEQ 会重算、REF 会跟随目标书签回正。但 F9 治不了样式丢失，也**会重算目录等所有域**，要提示老板先留副本。凡是涉及老板已经做过交叉引用的图表，**先报告再动手**，不要擅自重排。

## 9. 图表题注 / 交叉引用 审计（`scripts/audit_captions.py`）

老板问「题注插得对不对、图表有没有被正确引用」时用这个。**结论往往不是「有错」，而是「看着对、底层已经烂了」**。

### 9.1 先按顶层块切分（段落 / 表格），必须支持嵌套表格

正则 `<w:tbl>.*?</w:tbl>` 遇到嵌套表格会切错。用 `<w:tbl>` / `</w:tbl>` / `<w:p ...>` / `</w:p>` 的 tag 流 + 深度计数来切：
只有 `tbl_depth == 0` 时遇到的段落才算顶层段落。切完断言 `TBL 块数 == <w:tbl> 标签数`。

### 9.2 题注必须按 run 顺序做状态机解析，不能只看文本

题注段的典型形状是 `图 `（文本 run）+ [fldChar begin → instrText `SEQ 图 \* ARABIC` → separate → 缓存值 run → end] + ` 标题`（文本 run）。
用一个 token 流（`fldChar` / `instrText` / `w:t` / `bookmarkStart` / `w:drawing`）走一遍，得到 `前缀 / 域指令 / 域缓存 / 后缀`。**只看拼接文本会漏掉最关键的坑：**

| 类别 | 结构 | 为什么危险 |
|---|---|---|
| `OK` | `图 ` + 【SEQ=N】 + ` 标题` | 正常 |
| **`LEFTOVER`** | `图 ` + 【SEQ=1】 + `9 标题` | 显示出来正好是「图 19」，**看着完全正常**；按 F9 该域变 17 → 显示「图 179」。这是最阴的一类。判据：**域后面的第一个文本字符是数字**。 |
| `CACHE` | 域缓存 ≠ 可见号 | 域没更新过 |
| `HARD` | 整段没有 SEQ 域，号是手打的 | 不参与任何自动重排，容易被忽略 |

### 9.3 模拟一次 F9，才能说明「现在为什么不能更新域」

`SEQ 图` 的计数器是全文共享的：**按文档顺序第 k 个 `SEQ 图` 域，F9 后就是 k**。
把它算出来（`after_f9`）和可见号并排放，老板一眼就懂。若「可见号序列」根本不是 1..N 连续（多段重启、跨段重复），就说明题注编号是拼凑的——本例图号是 `1–15,17,18,19,20 → 1,2,3 → 1,2,3,4,33–39 → 16–25 → 50`，图 1/2/3 各出现三次。

顺带记一条实战结论：**只要存在 `LEFTOVER` 或编号重启，就不能建议老板按 Ctrl+A F9**，先修题注再说。F9 会把「看起来对」变成「明显错」。

### 9.4 交叉引用要分三种错，别混成一句「引用有问题」

1. **断链**：REF 的 instrText 目标名在 `bookmarkStart@w:name` 里找不到 → 按 F9 会变「错误！未找到引用源」。
   修法是**按上下文重新指向**，不是删掉。把 REF 所在段的正文 + 域缓存显示的号一起打出来，多半能确定它本该指哪个题注（本例 14 处全部可定）。
2. **显示号 ≠ 题注号**：书签能指到，但缓存里的号是旧的（老编号残留）。修好题注后 F9 会自愈。
3. **正文里硬写的 `图N / 表N`**：不是域，纯文本。**统计时要把域区间挖掉再搜**，否则会把交叉引用的显示值也算进去。
   做法：把每个域区间替换成一个占位符（如 `␣`），再对剩余文本跑 `[图表]\s*\d+`。这些是改号时最容易漏掉、也最容易被事后发现「你怎么没改」的地方；还会暴露出彻底不存在的号（本例正文里写着「图65」，全文没有图 65）。

### 9.5 产出形态

一张深色 HTML 审计表（块号 / 所属小节 / 类别色标 / 可见号 / 域缓存 / F9后会变成 / 可见文本），外加三张小表（断链+建议目标、显示号不符、正文硬写号）。比纯文字报告好用得多，老板能自己扫一遍定位。

## 10. 图表题注 / 交叉引用 修复（`scripts/fix_captions.py` + `scripts/verify_captions.py`）

审计之后真的要动手改时用这两个脚本。**核心原则：手术式定点修改，绝不整段重写题注段落。**

### 10.1 为什么不能整段重写题注段落

题注段落里除了文字，还藏着别的东西，整段重建会一次性全毁：

| 藏在题注里的东西 | 实例 | 后果 |
|---|---|---|
| `w:drawing`（图片） | 图片直接放在题注段里 | 图被删掉 |
| `_Toc*` 书签 | 34 个题注带 `_Toc18xxx` | **图目录/表目录的超链接全断** |
| 跨段 `bookmarkEnd` | 段内 3 个 end、2 个 start，其中一个 end 属上一段 | 书签计数不平，Word 报错 |

做法：只定位「编号数字」那一段字符/那一个 `<w:t>` 内容替换掉；要补 `_Ref` 书签就在
`</w:pPr>` 之后插 `bookmarkStart`、`</w:p>` 之前插 `bookmarkEnd`，原段落其他字节一律不动。
动手前先断言：`pPrChange/rPrChange` 计数为 0（否则 `.*?</w:pPr>` 会匹配到内层 `</w:pPr>`，插入点错位）。

### 10.2 致命 bug：改域缓存只能替「内容」，不能塞标签

`<w:t(?: [^>]*)?>([^<]*)</w:t>` 捕获的是 **group(1) = 内容区间**。
如果把这段内容替换成 `'<w:t>25</w:t>'`，就得到 `<w:t><w:t>25</w:t></w:t>` ——
**XML 合法、`ET.fromstring` 通过、自己的正则也能读出「25」，但 Word 会判定文件损坏。**
只替内容：`edits.append((off+a, off+b, str(N)))`，多余的显示 `<w:t>` 用 `''` 清空。
校验里必须加：`assert re.findall(r'<w:t(?: [^>]*)?>[^<]*<w:t[ >/]', xml) == []`。

### 10.3 正文硬写号的定位：必须建「可见文本 → XML 坐标」映射表

天真的两种做法都是错的：

- **只拼 `w:t` 文本**：跨 run 的「图」+「18」会被粘成「图18」，匹配到的位置在原始 XML 里找不到（旧脚本只好做脆弱的 delta 回算）。
- **把 XML 标签替换成等长空格**（中性化）：会引入**假空格**，「图18」被截成「图1」、「图65」被截成「图6」——
  匹配结果直接错（本例一度把 `图65→图37` 变成 `图6→图6`）。

正解 `vis_map(q)`：逐 `<w:t>` 文本节点把字符追加进可见串 `s`，同时记 `pm[k] = 该字符在 q 中的坐标`；
域区间的缓存值也追加进 `s` 但记 `pm[k] = -1`（不可编辑）。然后：

1. 在纯可见串 `s` 上跑 `([图表])\s*(\d{1,2})(?!\d)`；
2. `to_chunks(pm, ds, de)` 把数字区间映射回 q 的连续区间；任一位为 -1 就跳过（那是域里的号，不是硬写）；
3. 第一个区间写新号，其余区间清空（数字若被 run 拆开也能处理）；
4. 安全阀：`(?!\d)` + 编号长度 ≤2 + **该编号必须真的存在于某个题注**（否则跳过并打印告警），
   避免「图 2023 年」这类误伤。

### 10.4 三类改动的正确修法

**① `LEFTOVER`（域后残留数字）** —— `图 ` + 【SEQ 显示 1】+ 硬写 `9` → 显示「图 19」。
两步：把域缓存写成新号 N；再把域后**第一个 `<w:t>` 的前导数字**删掉
（判据：`可见号 == 域缓存 + 该前导数字`；若该数字后面不是空格，就换成一个空格，别删成没分隔）。

**② `HARD`（无 SEQ 域的纯手打题注）** —— 直接把数字换掉。若「图/表」与编号在 XML 里紧挨着
（`图20`），顺手补一个空格统一成 `图 20`；补空格时如果该 `<w:t>` 没有 `xml:space="preserve"`，
**必须同时把开标签改成带 preserve 的**，否则 Word 会吃掉前导空格。同时确认新号与含域题注的
序号一致（本例 11 个 HARD 全部对齐到与 SEQ 相同的 1–44 / 1–52）。

**③ 断链 REF 重指向 —— 就近题注会猜错，必须逐条读语义。**
本例 15 处断链里，按「最近题注」猜到 5 处是错的：
`block 840` 正文讲 DOMOO 框架、就近的 832 是别的框架（正解是 842）；
`block 906` 讲「边缘智能指导**流程**」（正解 905，不是 914）；`912/915` 才是指 914；
`856` 的第二个号在「表X~表Y」范围里应指**末位表**（865，不是 863）。
**正确做法**：把断链 REF 所在段的全文 + 候选范围内每个题注的标题都打出来，看句子里
「如图X所示」的宾语到底描述的是哪张图/表，逐条人工核定，写成 `REPOINT = {(书签名, 块号): 目标块}`。

### 10.5 正文硬写号也不能只信「旧号唯一」

作者手打号与题注号会**整体偏移**。本例 1.4.4 节手写号比题注号 **+1**：
`block 788` 写「表18和表19」实际指题注的 表17/表18；`block 816` 写「表23」实际指 表22。
靠「旧号唯一」会分别错指到 表18/表19/表23 的题注上。这类必须加人工指定表
`HARD_OVERRIDE = {(块号, '表18'): 789, ...}`，且**只在段落语义明确时**才用。
凡是「就近距离 > 12 块」的映射都打印 `!!远(d)` 告警，逐条复核。

### 10.6 改完必须跑的校验（`verify_captions.py`）

1. `ET.fromstring` 通过；**无嵌套 `<w:t>`**；`<w:p>/<w:r>/<w:tbl>/<w:rPr>/<w:pPr>` 开闭计数平衡。
2. `bookmarkStart` 与 `bookmarkEnd` 的 id 计数完全配对、书签名唯一。
3. **除 `word/document.xml` 外所有 zip 部件逐字节一致**（`z.read(name)` 直接比 bytes），部件清单一致。
4. 题注数 = 图片数（本例 44 图 / 52 表），图号 `1..N` 与表号 `1..M` 各自**严格连续**，且每个题注都有唯一 `_Ref` 书签。
5. 每个 REF 的 instrText 目标书签存在，且**显示值 == 目标题注的号**（0 例外）。
6. 标签计数差分只允许出现 `bookmarkStart/End` 的增量；`m:oMath`、`w:drawing`、`fldChar` 三者必须与源文件完全相等。
7. 逐条打印正文硬写号「现号 vs 最近题注」清单，供人工复看（不一致未必错，可能是前向引用）。

### 10.7 交付时要讲清的话术

- 编号方案是**老板决策**（全文连续 `图1–44/表1–52` vs 按章 `图x-y`），别自己定，先问。
- 交付物里必须写清「能不能 Ctrl+A → F9」，**这条结论取决于题注是否已全部域化**：
  - 只要有**任何一个题注的编号是纯文字**（无 SEQ 域），就必须写「不要在整篇文档上 Ctrl+A → F9」——
    全选更新会按域重算，域题注得到 1..N，与硬写号冲突。要更新就只选中单个题注按 F9。
  - 走完 §11（硬写题注全部补 SEQ 域）之后，结论**反过来**：Ctrl+A → F9 是**推荐动作**，
    编号完全由域驱动，刷新前后一致，可以放心让老板自己刷页码。此时交付话术要明确说「可以全选 F9」，
    否则老板会保留一条早已失效的禁令。
- 交付一份 HTML 说明页（三张表：题注重编号 / 交叉引用修复 / 正文硬写号同步），
  数据直接从修复脚本 `dump` 出来的 JSON 渲染，**保证说明页与成品同源**，不要另写一套解析逻辑（会与成品不一致）。

## 11. 硬写题注 → SEQ 域（把编号彻底交给域驱动）

这是 §10 的**收尾动作，也是整条链路里最值钱的一步**。判据：题注段「有题注样式 / `^[图表]\d+` 文本」但
`<w:instrText>` 里没有 `SEQ 图 \* ARABIC`。清单里这类题注的编号是死文本，`TOC \h \c "图"` 天生收不到它们。

**整段重写**（不要只替换数字）：
```
<w:r><w:t>图 17 标题</w:t></w:r>
=>
<w:r>{rpr}<w:t xml:space="preserve">图 </w:t></w:r>
<w:r>{rpr}<w:fldChar w:fldCharType="begin"/></w:r>
<w:r>{rpr}<w:instrText xml:space="preserve"> SEQ 图 \* ARABIC </w:instrText></w:r>
<w:r>{rpr}<w:fldChar w:fldCharType="separate"/></w:r>
<w:r>{rpr}<w:t>17</w:t></w:r>            ← 缓存值先写成正确号
<w:r>{rpr}<w:fldChar w:fldCharType="end"/></w:r>
<w:r>{rpr}<w:t xml:space="preserve"> 标题</w:t></w:r>
```
`rpr` 直接抄原 run 的 `<w:rPr>`（保持题注样式、字号、字体）。补完域后顺序**必须**仍是
「图→表、正文出现顺序」，并用 `SEQ 图` 总数 == 图题注数、`SEQ 表` 总数 == 表题注数 来断言。

配套动作：给这些题注补 `_Ref` 书签（供 REF 用）与 `_Toc` 书签（供清单用，见 §12），
用 `max(已有 bookmarkStart id)+1` 递增分配，别复用。

## 12. 「插图清单 / 附表清单」域缓存重建

`TOC \h \c "图"` 的缓存结果就是**一串普通段落**，每条长这样（结构固定，可直接当模板）：

```
<w:p>{pPr: pStyle=23 + 右对齐点线 tab}
  <w:r>{rpr}<w:fldChar w:fldCharType="begin"/></w:r>
  <w:r>{rpr}<w:instrText xml:space="preserve"> HYPERLINK \l _TocNNNNN </w:instrText></w:r>
  <w:r>{rpr}<w:fldChar w:fldCharType="separate"/></w:r>
  <w:r><w:t xml:space="preserve">图 1 </w:t></w:r>
  <w:r>{条目rpr}<w:t xml:space="preserve"> 标题文本</w:t></w:r>
  <w:r><w:tab/></w:r>
  <w:r><w:fldChar w:fldCharType="begin"/></w:r>
  <w:r><w:instrText xml:space="preserve"> PAGEREF _TocNNNNN \h </w:instrText></w:r>
  <w:r><w:fldChar w:fldCharType="separate"/></w:r>
  <w:r><w:t>1</w:t></w:r>
  <w:r><w:fldChar w:fldCharType="end"/></w:r>
  <w:r>{rpr}<w:fldChar w:fldCharType="end"/></w:r>
</w:p>
```

要点（踩过的坑）：

1. **首条条目段里嵌着 TOC 域定义**（`begin`+`instrText TOC …`+`separate` 三个 run 在 `pPr` 之后、
   第一条 HYPERLINK 之前）。整段替换时必须把这三个 run 摘出来，注入到新首条里，否则会**删掉整个域**。
2. 条目段的判定：段落含 `PAGEREF _Toc`。全文会得到三段连续区间——**正文目录 / 插图清单 / 附表清单**，
   用「索引断点」切分即可（`ent` 序列里 `ent[k+1] != ent[k]+1` 的位置）。
3. 外层的 TOC 域 `end` **不在**最后一条条目段里，而在其后某个（可能是带 sectPr 的）段落里 → 替换
   条目区间是干净的，不要去动后面那段。
4. **条目文本的 rpr 要用条目自己的**（普通条目是 `<w:rFonts w:hint="eastAsia"/><w:lang w:eastAsia="zh-CN"/>`），
   不要抄题注段 run 的 rpr（题注是 `pStyle=12`，字号不同）。**但下标要继承**：
   按题注里 run 的 `vertAlign` 拆成多段，下标段在条目 rpr 里加 `<w:vertAlign w:val="subscript"/>`。
5. **页码**：老条目 → 从 `PAGEREF … separate` 后面那个 `<w:t>\d+</w:t>` 精确取；新条目 →
   取相邻条目页码占位。页码由排版决定，交付时说明「定稿后 F9 刷一次页码，条目与编号不变」。
6. 新建条目段落时把 `w14:paraId="…"` **删掉**，避免复制出一堆重复 paraId。
7. 校验：`fldChar begin/separate/end` 三者计数必须**完全相等**且增量为 `2 × 新增条目数`；
   `HYPERLINK \l _Toc*` 集合 == `w:name="_Toc*"` 集合（悬空 0）。

### 12.1 只修「条目编号漂移」时：按锚点反查，别按顺序猜

文档被别人改过之后，常见症状是**清单里第 N 条起编号整体差 1**（因为前面插了图/表），
而条目顺序、标题都没变。这时**不要**按「第 k 条 = 第 k 个题注」去对齐，也别去比标题字符串——
直接用它自己的锚点，唯一且无歧义：

```python
# ① _Toc#### 书签 → 所属题注的 (kind, num)
toc2cap = {}
for 每个含 SEQ 图/表的段落:
    (kind, num) = 从渲染文本 ^[图表]\s*(\d+) 取
    对该段所有 w:name="_Toc*" 书签: toc2cap[name] = (kind, num)

# ② 清单条目：PAGEREF 的锚点 → 应显示的编号
for 每条含 PAGEREF _Toc#### 的段落:
    if 锚点 not in toc2cap: continue      # ← 正文目录条目，自动跳过
    kind, num = toc2cap[锚点]
    在 PAGEREF 之前的 <w:t> 拼接串里找 ^[图表]\s*(\d+)，替换那串数字
```

要点：
- **正文目录（`TOC \o`）条目的锚点指向章节书签，不在 `toc2cap` 里 → 天然被排除**，
  不会误改「1.2 概述」这类条目。命中统计应恰好等于 `图题注数 + 表题注数`（例：44 + 52 = 96）。
- 编号常在**独立的 `<w:t>`** 里（`<w:t xml:space="preserve">表 2 </w:t>`），但也可能和标题同 run →
  先拼接 PAGEREF 之前所有 `<w:t>` 文本，在拼接串里定位数字，再映射回具体那个 `<w:t>`。
- 改完校验：图/表清单编号序列 == `1..N`（无重复、无缺号、升序）。
- 页码不用动（那是 `PAGEREF` 的缓存，属于排版）。


## 13. 字符级：符号 → 真下标（含「上标误用」）

场景：正文把 `Psim / IGDoffline / APsmall / Ectx / dt` 写成纯字母串，而同段公式里已是 `P_sim` 形式。
目标：拆 run + 加 `<w:vertAlign w:val="subscript"/>`，**不动字号字色**。

做法（一次把一段重建成 run 序列，比插入标签稳）：

1. **逐段处理，不要逐「顶层块」处理**。按 `<w:tbl>` 切块会让一整个表格变成一个块，单元格之间没有文本边界，
   于是 `APsmall` 的边界守卫会被**前一个单元格末尾的 `AP75`** 干扰而漏掉。
   用「深度感知的 `<w:p>` 切分」，表格单元格里的段落各自成段。
2. run 解析正则**必须容忍标签间换行**：Word 写出来的是 `<w:r>\n<w:rPr>…</w:rPr><w:t>…</w:t>\n</w:r>`。
   写成 `^(<w:r[^>]*>)((?:<w:rPr>.*?</w:rPr>)?)((?:\s*<w:t…>…</w:t>)+)\s*(</w:r>)$`（`re.S`）否则整块 run 被判为不可重建。
3. 建「可见字符 → (run, text片, 片内偏移)」映射表；token 命中后按 `base_len` 切 `split1`，
   把 `[split1, end)` 全标为下标。
4. **跳过已是下标的**：`all('w:vertAlign w:val="subscript"' in rpr for i in range(split1,end))`。
   注意判据必须是 **subscript**——只判 `'vertAlign' in rpr` 会把**上标误用**（`d^t` 本应是 `d_t`）当成已完成而漏修。
   本例 4 处 `dt/ds/de` 的后缀就是被设成了 `superscript`。
5. 生成下标 run 时先把 rpr 里已有的 `<w:vertAlign …/>` **删掉**再插入 subscript，否则会出现两个 vertAlign。
6. **不要碰域缓存里的文本**：TOC/REF 的缓存 run 与正文 run 混在同一段，必须先建「位置 → 是否在
   `fldChar separate`..`end` 之间」的掩码，只处理非缓存 run；清单条目里的符号留给 §12 重建时一起生成。
7. 零宽空格 `U+200B` 多藏在 `<m:t>` 里（`<m:t>\u200b</m:t>` 整段就是一个 ZWSP，用来撑住空的
   `m:sup`/`m:sub`）。删掉字符即可，**不要删整个 `<m:r>`**（父级 `m:sup` 变空反而更危险）。
8. 公式内的 ASCII `...` 换成 `…`（中文体例），全文通常只有 1 处。
9. 段落重建与「字面锚点替换」会**互相重叠坐标**（锚点常落在被重建的段落里）。
   稳妥顺序：先做所有段落重建（按坐标倒序），**最后**再做字面锚点替换（`str.replace` + 断言命中次数）。

## 14. 分层顺序与回归清单

固定顺序，每层做完立刻回归，别攒到最后：

```
① 题注重编号（域缓存 + 硬写号）→ 断言 图1..N / 表1..M 连续
② 硬写题注补 SEQ 域           → 断言 SEQ 图==图题注数、SEQ 表==表题注数
③ 断链 REF 重指向 + 显示号同步 → 断言 REF 目标 0 断链、显示号==目标号
④ 补的 `_Ref` 书签跨度收窄     → 断言「过宽书签数==0」（判据见 §15）
⑤ 正文硬写图表号校正          → 人工核定优先，其次「同类题注就近 ±12 段」
⑥ 清单缓存重建 + 补 _Toc       → 断言 条目数==题注数、锚点 0 悬空、fldChar 三计数相等
⑦ 字符级（下标 / 零宽 / 省略号 / 括号）→ 断言 subscript 净增数 == 命中数
⑧ 终检：按 §15 的 REF 语义重算 → 断言「缓存与语义不符==0」（不能只比 `图 N`）
⑨ 正文纯文本图表号 → REF 域（§17）→ 断言 REF 总数 == 基线+命中数、三计数配平、
   可见文本逐段 diff「仅图/表与编号之间的空格变化、骨架不变」
```

**全程只重写 `word/document.xml`**，其余部件 `zo.writestr(it, z.read(it.filename))` 逐字节照抄；
`word/media/*` 必须逐字节一致（可用它来证明没有重编码图片）。

## 15. 书签跨度决定交叉引用的「Word 语义」——补 `_Ref` 书签必须只包编号

**这是 §11「硬写题注 → SEQ 域」最容易留下的隐性坑。**

为硬写题注补 `SEQ` 域时，通常也要补一个 `_Ref####` 书签当交叉引用目标。**书签该包多宽**决定了
Word 按 F9 重算后显示什么：

| 书签跨度 | `REF x \h` 的 Word 语义 | 题注段 XML 长度 |
|---|---|---|
| 只包 `"图 "` + `SEQ` 域 | 显示 `图 5` ✅（作者本意） | ≈ 280 |
| 包住整段题注（编号+标题） | 显示 `图 5 少样本对比增强画像微调方法架构图` ❌ | ≈ 390–650 |

Word 原生题注（「插入题注」生成）永远是**前者**，且同段另有一个 `_Toc####` 书签只包标题：

```
[BM:_Ref9866]图 <SEQ 图 \* ARABIC | 5>[end]   [BM:_Toc26586] 少样本对比增强画像微调方法架构图[BMend#16]
```

**补书签时照抄这个形状**：`_Ref` 的 `bookmarkEnd` 落在 SEQ 域的 `fldChar end` 之后、
`_Toc` 的 `bookmarkStart` 之前（两者**相邻不重叠**）。

**症状与自证**：缓存写对了（显示 `图 5`）、断链 0、字号都对，一切"看起来没问题"——
但只要在 Word 里 **F9 / 打印 / 导出 PDF** 触发全量域更新，那些引用会**就地膨胀成整段题注全文**。
所以「缓存文本 == `图 N`」是**必要不充分**的检查。

**正确的验收口径**：按 `REF bookmark \h` 语义**重算**一遍每个 REF 应显示什么，再和文件里的缓存比：

```python
def expected(x, bookmark_name):
    """按 Word 语义：REF 显示 bookmark 覆盖范围内的文本（内嵌域用其缓存值渲染）"""
    s0, s1 = bm_start_end_offset(x, bookmark_name)   # bookmarkStart 之后 ~ bookmarkEnd 之前
    return render(x[s0:s1]).strip()                  # render() 见 §10.3 的域掩码渲染
```

**发现已存在过宽书签时的修法**（长度守恒地移动 `bookmarkEnd`，44 个一起改也不会错位）：

```python
# toc = 该段 _Toc bookmarkStart 的起点；e0,e1 = 该 _Ref 的 bookmarkEnd 区间
x = x[:toc] + x[e0:e1] + x[toc:e0] + x[e1:]
```

**判据**：`_Ref` 跨度的 XML 长度 > 350 且内部含 `_Toc` bookmarkStart → 过宽，需收窄。

> **反向对照**：上面是「过宽 → 收窄」。若题注**已有 `SEQ` 域但根本没有 `_Ref` 书签**，
> 走另一方向「缺失 → 补建」——用 `docx-numbering-xref-pipeline/scripts/add_ref_bookmark.py`
> （`<in.docx> <out.docx> [--dry]`）。**两者共用同一判据**：新跨度 XML 长度 < 350 且内部不含
> `_Toc` 书签；命名取现有 `_Ref\d+` 最大值 +1、`w:id` 取现有最大 bookmark id +1。

**顺带的坑**：重建 `document.xml` 时**不要用 `''.join(段落切片)`**。只取 `<w:p>` 会让
`<w:body>` / `<w:sectPr>` / 表格包装等段外内容全部丢失，报错却是误导性的
`ET.ParseError: unbound prefix`。必须**按 `(start, end, newtext)` 区间倒序替换**。
（另：`<w:fldChar w:fldCharType="separate"/>` 实长 37、`...="end"/>` 实长 32，别写 `+34` / `+33` 这类魔法数。）

**改域缓存必须「增量重建」，不能按旧偏移逐个替换 `<w:t>`**：一个域的结果常被 Word 拆到
**多个 run**（例：`<w:t>表 34 </w:t>` + `<w:t>不同离线MOO方法…</w:t>`）。若先替换第一个 `<w:t>`
（长度变了），第二个 `<w:t>` 的 `start/end` 就已失效，替换会插进 XML 标签中间，报的却是
`ParseError: not well-formed (invalid token)`。正确写法——一次遍历、边拼边写：

```python
out, last, j = [], 0, 0
for t in WT.finditer(region):                 # WT = <w:t ...>(...)</w:t>
    out.append(region[last:t.start()])
    out.append('<w:t xml:space="preserve">%s</w:t>' % (want if j == 0 else ''))
    last = t.end(); j += 1
if j:                                         # 只有一个 run 时也走这条
    out.append(region[last:])
    q = q[:cstart] + ''.join(out) + q[cend:]
```

**改完立刻 `ET.fromstring` 逐段验一次**，别攒到最后——否则定位成本翻十倍。

## 16. 交付后文件被 Word/WPS 重存过 → 先查「半更新」而不是重跑管线

用户回来说「检查一下」，而桌面那份的指纹（size / md5 / `document.xml` 长度 / `w14:paraId`）与交付件**全不同**时：

1. **先看锁文件**：`~$<文件名>.docx` 存在、且 `open(path,'r+b')` 抛 `Permission denied`
   → 用户当前正打开着它，**不要写回原路径**，另存新文件名。
2. **再判内容是否同源**：把两份的**非空段落可见文本**做 `difflib.SequenceMatcher` 序列对齐。
   若只有少量 `replace`/`insert` → 内容同源，只是被重存（Word 可能顺手拆合段落、归一化空格、
   重新生成 `paraId`）→ **可以安全以干净基线重建**，不会丢用户内容。
3. **典型"半更新"症状**：一部分域缓存是新值、一部分还是旧值（例如图清单第 N 条起整体差 1、
   若干 REF 差 1）。这既不像"没更新"也不像"已更新"，就是 Word/WPS 保存时只重算了部分域。
   → 结论口径：**以自己那份缓存自洽的基线重建**，别在用户那份上逐条打补丁。
4. 汇报时必须说清 **哪一份被谁改过**（给出 size/md5/时间戳），并说明原文件未被改动。

**别把「Word 另存」误判成「文件坏了」**：Word/WPS 走一次「另存为」会**必然**重写
`docProps/app.xml`、`docProps/core.xml`、`word/fontTable.xml`、`customXml/item*.xml`、
`word/_rels/document.xml.rels`，并把 `word/media/*` **按序重命名**（例：`image2.jpeg`+`image3.png`
→ `image2.png`+`image3.jpeg`，扩展名跟随实际编码），还会重生成全部 `w14:paraId`、
可能拆合段落（段落数 +N）、把 zip 体积顶回源文件量级。
所以「除 `document.xml` 外部件逐字节一致」**只在刚交付那一瞬成立**，用户动过一次就必然不成立。
真正要分清的是：差异**只集中**在上述"另存必改"部件 → 同源、正常；
出现 `word/media/*` 增删、`<w:drawing>` 计数变化、段落数变化 → **用户确实改了内容**，
域缓存必定过期，按 §14 重跑对应层。可一条命令验完：
`~/.workbuddy/skills/docx-numbering-xref-pipeline/scripts/verify_all.py <docx> [--base 改前备份.docx]`。

## 17. 正文纯文本「图N / 表N」→ 真正的 REF 交叉引用域

**场景**：题注已经是 `SEQ` 域 + `_Ref####` 书签了，但正文里的引用还是**手打的纯文本**
（`如图16所示`、`结果如表 23 所示`）。用户说「换成真正的 REF 域」——即让这些引用在 F9 后
自动跟随题注编号。

脚本三件套（都已在 `scripts/`，可直接跑）：

| 脚本 | 作用 |
|---|---|
| `recon_hardref.py` | 侦察：列出所有硬写引用的**所在段 / run 结构 / 分类 A/B/C** |
| `build_caption_ref_map.py` | 建 `(图/表, num) → (_Ref####, 渲染文本)` 映射（96 条，题注段反查，唯一无歧义）|
| `fix_hardref_to_ref_field.py` | 改写器：`fx_hardref.py  <in> <out> [--dry]`，幂等 |
| `diff_visible_text.py` | 验收：两版逐段可见文本 diff + 结构计数对比 |

### 17.1 先分类，再决定改法（`recon_hardref.py` 的输出）

```
A_整段就是编号   run 的文本恰是「图21」          → 整 run 换成域块
B_段内子串       run 内长文本里的子串「…如图16所示。」 → 拆 run：前缀 + 域块 + 后缀
C_跨多段         「图」在 run1 末尾、「16」在 run2  → 跨 run 区间重建
```

**不要按 A/B/C 写三套代码**。统一抽象成「**受影响 run 区间整体重建**」：
把命中字符首尾映射到 run，得到区间 `[run_start, run_end]`；同段多处命中若区间重叠/相邻就**合并成一组**；
每组把区间内的 `<w:t>` 文本拼起来当字符流，边扫边输出「文本 run + 域块 run」。

### 17.2 三个必须踩对的点

**① 偏移必须用 `<w:t>` 的内文本起点，不是标签起点。**
`visible_segs()` 返回 `(m.start(), m.end(), text, m.start(1), m.end(1))`——
算绝对坐标要用 **`m.start(1)`（第 4 个元素）**。用 `m.start()` 会左偏一个 `<w:t xml:space="preserve">`
的长度（≈25 字符）；短 run（如 A 类 25 字符的 `图21`）刚好还落在同一 run 里而不报错，
但长 run 边界处就会取错 run —— 属于**静默错误**。

**② 保留原 run 的 `rPr`。** 重建出的每个 run（`begin`/`instrText`/`separate`/缓存/`end`，
以及切出来的前缀、后缀 run）都复制**原 run 的 `<w:rPr>`**。
本套件的文档里 Word 自带的 REF 缓存 run 是**无 rPr**的；照抄它会让缓存文本回落到段落默认格式，
在 `rStyle`/加粗段落里肉眼可见地变样。**有 rPr 更安全**。

**③ 校验代码里的多行 raw-string 拼接别漏出裸分支。** 反面教材：

```python
BADRE = re.compile(r'<w:br/>|<w:br\b|<w:tab/>|<w:tab |>|<w:cr/>|'  # ← 「<w:tab |」手误多打一个 >
                   r'<w:sym\b|...')
```
`<w:tab |>|` 会被 `re.split('|')` 拆出**一个裸 `>` 分支**，于是 `>` 匹配一切、
`BADRE.search()` 对任何片段都命中 → 37 处全部被拒、报告成 `bad_content`。
用**单词边界**写法，天然避免这类跨界误配：

```python
BADRE = re.compile(r'<w:fldChar|<w:instrText|<w:drawing|<w:pict|<w:object|'
                   r'<w:br\b|<w:tab\b|<w:cr\b|<w:sym\b|<w:noBreakHyphen|<w:softHyphen|'
                   r'<w:footnoteReference|<w:endnoteReference|<w:commentReference|'
                   r'<w:proofErr|<w:bookmarkStart|<w:bookmarkEnd')
```
（`<w:tab\b` 不会误伤 `<w:tabs>`——`b` 后接 `s` 不构成词边界。）

### 17.3 生成的域块（与 Word 原生一致）

```xml
<w:r>{rPr}<w:fldChar w:fldCharType="begin"/></w:r>
<w:r>{rPr}<w:instrText xml:space="preserve"> REF _Ref900192 \h </w:instrText></w:r>
<w:r>{rPr}<w:fldChar w:fldCharType="separate"/></w:r>
<w:r>{rPr}<w:t xml:space="preserve">图 16</w:t></w:r>
<w:r>{rPr}<w:fldChar w:fldCharType="end"/></w:r>
```

**缓存文本取「题注自身的渲染文本」**（题注段 `_Ref` 书签内的 `<w:t>` 拼接，如 `图 16`，**含空格**），
不要沿用正文原来的 `图16`。理由：正文 96 条题注里渲染就是 `图 16`，文档里已有的 53 个 REF 缓存
也都是这个形态；缓存=`图16` 会让「F9 前」和「F9 后」显示不一致。代价是 37 处里约 24 处会产生
「图16 → 图 16」的**空格可见变化**，验收时要**明确报出来**，别当成 bug。

### 17.4 验收口径（缺一不可）

```
REF 域数     基线 + 命中数（本次 53 → 90）。基线要用 len(re.findall(r'REF\s+_Ref\d+', x)) 现算：
             本文档 REF 有两种 instrText 形态（`REF x \h` 52 个 + `REF x \h \* MERGEFORMAT` 1 个），
             硬编码 52 会误报。
① 语义      audit_ref_semantics.py → 目标书签缺失 0 / 缓存与语义不符 0 / 过宽书签 0
② 配平      bookmarkStart==bookmarkEnd；fldChar begin==separate==end；域深度扫描最小深度>=0、结束深度==0
③ 残留      recon_hardref.py 重跑 → 「共 0 处」
④ 可见文本  diff_visible_text.py → 差异段落数与命中段落数吻合，且每处
             re.sub(r'\s','',旧) == re.sub(r'\s','',新)、去编号后的骨架文本完全相同
⑤ 结构      <w:tbl>/<w:drawing>/<w:tblGrid>/SEQ 域/书签计数三者前后相等；段落数相等
⑥ 部件      除 word/document.xml 外，其余 zip 条目**逐字节相同**、条目顺序相同
⑦ 打开      python-docx 能打开（`docx.Document(路径)`）
```

### 17.5 交付纪律

先 `--dry` 干跑看报告 → 备份 → 写 staged 文件 → 全套验收 → 才就地覆盖。
`--dry` 同样会跑完所有断言（REF 计数、fldChar 配平），所以断言失败在写盘前就能暴露。
