# docx 统一处理流水线（总编排）

**这是编排层，不是实现层。** 它自己不写一行 OOXML 处理代码，
只负责：**排顺序、设闸门、统一改动事项单、把活派给下面三个 skill**。

```
docx-unify-pipeline（本 skill）        ← 七阶段编排 + 门禁 + 统一 CRS
├── docx-format                        ← 权威实现：spec 真源 + run/styles/lint/revise + CRS 唯一实现
├── docx-numbering-xref-pipeline       ← S2 编号与交叉引用治理（5 阶段 + verify_all.py 13 项）
└── docx-formula-image-to-omml         ← 工具层：公式图→OMML、各类修复脚本
```

**铁律：本 skill 不重复实现任何一项能力。** 缺什么就往对应 skill 加，
不要在这里另写一套——两套实现同时演进，同一份文档会跑出两种结果。

---

## 🛑 两道硬门禁（不可绕过）

### 门禁一：先出清单、批准后执行

**任何写盘修改之前，必须先产出「改动事项单（CRS）」可勾选清单，拿到老板逐条批准。**

适用**所有**会改文档的阶段：S2 的修复脚本、S3 的补题注、S4 的排版、S6 的落盘。
**只读动作不受限**：`inspect`、`styles`、`lint`、各类 audit 随时可跑。

清单有两种载体，**规矩不同**：

| 载体 | 什么时候用 | 批准形式 |
|---|---|---|
| **HTML 可勾选页** | 默认。逐条复选框、按档筛选、导出 `approved.json` | 老板勾完导出 |
| **Markdown 表格** | 老板明确说"给我个表"、或环境不方便开 HTML 时 | 老板在对话里逐条回话 / 口头批量授权 |

无论哪种载体，**最终都必须落成同一份 `.json`**（`decision` 字段是唯一依据）。
口头授权照样有效，但要按对应关系落成 decision（见
`docx-format/references/change-request-sheet.md` §8）。

**四条不可破的规矩**：

1. **没出清单 → 拒绝写盘。** 不许"我先改了再说""改完再给你看清单"。
   老板要的是**事前**否决权。
2. **清单出了但没回话 → 拒绝执行**，并显式回话"清单已就绪，在等你勾选"。
   **沉默不是同意。**
3. **只执行 `decision=approved` / `modified` 的项。** 未勾选项原样不动，
   且**必须**出现在回执的「未勾选未改」栏里——不得静默丢弃。
4. **批准 ≠ 跳过安全措施。** 拿到批准后照旧：备份 → `--dry` 干跑 →
  `verify` 全绿 → 才写盘。批准的是"改什么"，不是"跳过验证"。

### 门禁二：修订模式 + 逐条批注

**改动一律以 Word 修订模式写入**（`w:ins` / `w:del`），并**给每一处挂批注
说明改动原因**。老板要能在 Word 里逐条接受/拒绝，并看懂每处为什么改。

由 `docx-format` 的 `revise` 命令保证（`--crs <清单> --approved <裁决>`）。
`revise` 自带不变量校验：段落数 / 表格数 / 图片数 / 书签数 / 域三态计数
**必须全不变**，否则拒绝落盘。

**例外**：纯结构操作（S2 的编号重排、S4 的表格边框）本身不产生文字修订，
但**仍必须**出清单、拿到批准、并在回执里逐条交代改了什么。

## 快速开始

```bash
PY=~/.workbuddy/binaries/python/envs/default/Scripts/python.exe
S="C:/Users/14711/.workbuddy/skills/docx-unify-pipeline/scripts"
D="C:/Users/14711/.workbuddy/skills/docx-format"
DOCX="课题3-中期科技报告.docx"

# S0 备份 + 建账本
cp "$DOCX" "${DOCX%.docx}_备份_$(date +%Y%m%d_%H%M%S).docx"
"$PY" "$S/pipeline_state.py" init "$DOCX"
"$PY" -m docxfmt inspect "$DOCX"

# S1 样式确认单 → 交给老板
"$PY" -m docxfmt styles "$DOCX"
# 🛑 等老板确认 / 手改 / 导出 _样式确认单.json

# S2 编号与交叉引用治理（详见 docx-numbering-xref-pipeline）
# S3 题注补插 + 硬写引用转真 REF 域

# S4 排版六条（逐条出 CRS 行）
# S5 内容校验 + 事实核查
"$PY" -m docxfmt lint "$DOCX" --spec "${DOCX%.docx}_样式确认单.json"

# 合并所有来源为唯一一份清单 → 交给老板勾选
"$PY" "$S/crs_merge.py" --docx "$DOCX" \
    --in "${DOCX%.docx}_待拍板.json" \
    --in "${DOCX%.docx}_编号治理.json" \
    --in "${DOCX%.docx}_改动事项.json" \
    -o "${DOCX%.docx}_统一改动事项.json"

# S6 写盘前自查 → 修订落盘 → 重算域
"$PY" "$S/pipeline_state.py" check --stage S6
"$PY" -m docxfmt revise "$DOCX" \
    --crs "${DOCX%.docx}_统一改动事项.json" \
    --approved "${DOCX%.docx}_approved.json" \
    -o "${DOCX%.docx}_修订.docx"
"$PY" -m docxfmt fields "${DOCX%.docx}_修订.docx" \
    -o "${DOCX%.docx}_修订_域重算.docx"
```

**完整剧本（每阶段的目标/命令/产物/闸门/断言/失败处理/坑）见
`references/pipeline-stages.md`。**

## 状态账本与门禁机

七阶段跨三个 skill，中间还有 5 道人工闸门。**没有账本必然出事故**：
勾的是这一轮的清单、执行的是上一轮排好的旧单；中途 Word 重存过，
段落号全变了还在用旧坐标。所以每一步都记账：

```bash
S=".../docx-unify-pipeline/scripts"

"$PY" "$S/pipeline_state.py" init "$DOCX"                    # 建账本（记指纹）
"$PY" "$S/pipeline_state.py" status                          # 看进度 + 指纹是否还成立
"$PY" "$S/pipeline_state.py" set S1 blocked --note "等老板勾"  # 标阶段状态
"$PY" "$S/pipeline_state.py" gate S1 approved --by 老板        # 记闸门结论
"$PY" "$S/pipeline_state.py" artifact S1 "<样式确认单>.json"    # 登记产物
"$PY" "$S/pipeline_state.py" next                            # 下一个该做的阶段
"$PY" "$S/pipeline_state.py" check --stage S6                # 🛑 写盘前自查
```

账本落在 `<文档目录>/_unify/pipeline_state.json`。

**`check` 是写盘前的最后一道闸**，三项都过才放行：

| 检查 | 不通过 |
|---|---|
| 目标文档 md5 是否还等于账本记的 | `exit 5`「文档已被改过，账本作废，重新出单」 |
| 前面所有 `老板` 档闸门是否都已 `approved` | `exit 4`「没有批准就推进了」 |
| 已登记的产物是否都还在 | `exit 4`「产物不见了」 |

> **指纹不符一律重新出单，不要"差不多"地套用旧单。** Word 重存会重排段落号，
> 旧单的 `where.para` 全部失效，照旧单执行会改错地方（这是最隐蔽的一类事故）。

## 统一改动事项单（多来源合并）

一条链路上会冒出好几份清单（`propose` 的层级疑点、编号治理的病灶、
`lint` 的正文问题、事实核查的结论）。**让老板分别勾 4 份清单必然出事** ——
勾了 A 忘了 B、同一处被两条不同建议改两遍、`CR-ID` 属于哪份单说不清。

所以：**出单阶段允许多来源 → 勾选阶段只有一份 → 执行阶段只读这一份。**

```bash
"$PY" "$S/crs_merge.py" --docx "$DOCX" \
    --in a.json --in b.json --in c.json \
    -o "${DOCX%.docx}_统一改动事项.json"
```

`crs_merge.py` 做四件事：

1. **验指纹**：所有来源单的 `target.md5` 必须一致，不一致直接 `exit 5`；
2. **去重**：同一处（段落 + 改前 + 改后）在多份单里出现 → 合成一条，
   档位取最高（`S>A>B>C`），`source` 记成 `lint+propose`，
   并保留全链被合并的 `merged_from`（谁提过这件事）；
3. **暴露冲突**：同一处被建议改成**不同结果** → 不自己选，
   写进 `baseline.conflicts` 并在 stdout 打印，**交给老板裁**；
4. **统一编号**：按 档位 → 段号 排序，重排 `CR-001..N`；
   同时输出 `<清单>_溯源.json` 记录每条 CR 原本来自哪份单的第几条。

## 闸门交互：清单怎么给老板

### 默认：HTML 可勾选页

`<文档名>_统一改动事项.html` —— 单文件、零外部依赖、深浅色自适应。
功能：逐条勾选 · 全选/全不选/**按档勾选（S/A/B/C）** · 按档/风险/来源筛选 ·
实时统计「已勾 N / 共 M」· 一键导出 `approved.json`（下载 + 复制到剪贴板两条路）。

老板勾完导出的 `approved.json` 就是裁决结果。格式见
`docx-format/references/change-request-sheet.md` §7。

### 备选：Markdown / 对话表格

老板说"给我个表"或环境不方便开页面时，用这个格式（**列要齐**）：

| 勾选 | ID | 档 | 位置 | 现状 | 建议改为 | 依据 | 风险 | 影响面 |
|---|---|---|---|---|---|---|---|---|
| [ ] | CR-001 | **S 必改** | 5.2 · 段 1487 | 中国电子学会科学技术奖一等奖 | 二等奖 | 学会官网获奖名单（访问 2026-10-09） | 低 | 无 |
| [ ] | CR-004 | **B 建议** | 全文 · 68 处 | 「图 N所示」 | 保持「图 N」不动 | 本轮口径：正文去空格、题注保留 | 低 | 无 |

老板在对话里回话即可，按话术映射落成 decision：

| 老板说 | 落成 |
|---|---|
| 「全部同意」「都改」 | 全部 `approved`，`gate.state=approved` |
| 「除 CR-007 外都同意」 | 除该项 `rejected`，其余 `approved` |
| 「只改 S 档」 | `grade=S` → `approved`，其余 → `rejected` |
| 「先不改」「再想想」 | 全部 `rejected` |
| 「CR-005 改成 XXX」 | 该项 `modified` + `after_override="XXX"` |
| 「CR-003 不用了」 | 该项 `rejected` |

**沉默不是同意。** 没回话就保持 `awaiting_approval`。

## S4 六条硬要求（老板最在意的部分）

| # | 要求 | 实现路线 | risk |
|---|---|---|---|
| ① | 文档 > 100 页时，**一级标题分页** | 静态估页数（≥100 才插）→ `pagebreak.before_heading=[1]` | mid |
| ② | **数字与中文、英文与中文、公式与中文之间无空格** | 静态正则 `RE_CJK_SPACE` / `RE_LATIN_SPACE` | low |
| ③ | 正文每页**不出现 ≥4 行空白** | **渲染级**：COM 导 PDF 逐页量行 | mid |
| ④ | **不出现单字加标点独占一行** | **渲染级**：PDF 文本层数行内字符 | mid |
| ⑤ | **题注与对应部分同页** | **渲染级**：题注段与目标图/表的页号比对 | mid |
| ⑥ | **表格美化**：数据表三线表 / 文本表全框 / 行列宽高合审美 | 静态：算每格平均字符数判类型 → 改 `tblBorders` | mid |

**③④⑤ 静态 XML 量不出来**（"这页有多少行""这行塞下没""题注和表同页没"
只有渲染后才知道），所以走**静态 + 渲染级混合**：
能静态判的静态判（快、可回归、可 CI），必须看分页的走 Word/WPS COM 导出 PDF 后量页。

**拿不到 COM 时降级**：③④⑤ 只出"建议处理位置清单"，让老板在 Word 里手工挪。
**绝不瞎猜分页结果然后自动改。**

### ⚠️ ② 的口径冲突（唯一一条会推翻上一轮结论的规则）

本轮规则「数字与中文之间**不要**空格」与上一轮 CR-004
「`图 1所示` → `图 1 所示`（**加**空格）」**精确矛盾**。

**已确认口径：正文去空格，题注保持「图 1」。**

- `精度 0.8554` → `精度0.8554`　✅ 去
- `图 1所示` 里的 `图 1`　→　**不动**（题注的空格是体例要求）
- `deep learning`、`[1] 张三.`、`（1）`　→　不动

**执行 S4-② 之前，必须把这条口径念一遍给老板**，因为它是唯一一条
会覆盖既有结论的规则。六条要求逐条出 CRS 行（不合成一条"排版优化"），
老板可能只要 ②⑥，不要 ①③④⑤。

**六条的判定细节、表格几何经验值、例外清单见 `references/pipeline-stages.md` §S4。**

## S5 事实核查（联网）

**范围：事实性内容——主要是奖项、新闻、官方通报。不含小范围事件。**
（小范围事件没有公开来源，查不到，硬查只拖进度。）

一句话判据：**这条断言有没有可能有一个权威公开来源？**

- 有 → 查。用 `WebSearch`。**不能凭记忆回答**——奖项的届次、等次、
  主办单位最容易串。
- 没有 → 标注 `out_of_scope` 留一行，别让它悄悄消失。

判定**四态**：`supported`（有权威来源，四格全对）/ `contradicted`（明确矛盾）/
`insufficient`（查不到公开来源）/ `out_of_scope`（小范围事件）。

| 判定 | 落档 |
|---|---|
| 部分不符 / 矛盾 | **S 档**，按来源改正 |
| 查不到公开来源 | **C 档**，标注"未找到公开来源"，交老板定 |
| 证实 | `closed`，进「已核」区留档，**不改文档** |

**`insufficient` 绝不等于错。** 把"查不到"写成"疑似错误"是最严重的误报。

**完整协议（源的可信度三级分类、检索规则、四格核对、核查表格式、六条禁令）
见 `references/fact-check-protocol.md`。**

## S6 交付纪律

**三栏回执，缺一不可**：

| 栏 | 内容 |
|---|---|
| 已改 | N 项，逐条 `CR-ID + 改前 → 改后` |
| 未勾选未改 | M 项，逐条 `CR-ID`（让老板知道哪些还挂着） |
| 失败 | K 项，逐条 `CR-ID + 原因`（含 `_Skip` 跨 run 匹配失败） |
| 安全 | **备份路径 + md5** |

**交付话术必须包含**：

1. 改了哪些（数量 + 分类计数）
2. **可见变化清单**（例："24 处 `图16` → `图 16`"），**别让老板自己发现**
3. 改前备份的路径与 md5
4. 一句关键提醒：**域缓存不会自动重算**，在 Word 里 `Ctrl+A` → `F9` 一次即可
5. 修订模式下**接受/拒绝**的入口（在 Word「审阅」选项卡）

## 退出码约定（全链路统一）

| 码 | 含义 | 处置 |
|---|---|---|
| 0 | 成功 | — |
| 2 | 验收失败（`verify_all.py` / `verify` 有 FAIL） | 禁止交付，回到对应阶段 |
| 3 | **无 CRS** —— 没出清单就要执行 | 拒绝写盘，先出清单 |
| 4 | 闸门未满足 / 无可执行项 / 清单全被否 | 回话"清单已就绪，在等你勾选" |
| 5 | **指纹不符** —— 文档在出单后被改过 | **重新出单**，不套旧单 |
| 6 | 用法错误 | 查参数 |

---

## 不要做

- **不要在没出清单、没拿批准的情况下写盘。** 这是本 skill 存在的理由。
- **不要绕过修订模式直接改。** 老板要能逐条接受/拒绝。
- **不要在 `lint` / `styles` 里顺手改文档。** 它们只出单。
- **不要在本 skill 里另写一套 OOXML 处理代码。** 缺能力就往对应 skill 加。
- **不要凭记忆做事实核查。** 所有 `supported` 判定都必须有本次检索的 URL。
- **不要把 `insufficient`（查不到）写成 `contradicted`（矛盾）。**
- **不要在指纹不符时套用旧单。** 重新出单。
- **不要让 ③④⑤ 在没有 COM 的情况下自动改。** 没量到分页就不许动排版。
- **不要静默丢弃未勾选项。** 必须进回执的「未勾选未改」栏。
